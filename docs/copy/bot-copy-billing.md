# תוספות טקסט — תשלום מתוך וואטסאפ (HYP, לחיצה אחת)

> משלים את `bot-copy.md` §6 (אותן מוסכמות). מיושם ב-`lib/copy/bot-billing.ts`; בדיקה מוודאת שכל id כאן קיים בקוד.
> מחרוזות קיימות שממשיכות לשמש: `bill.cancel_confirm`, `bill.cancelled`, `bill.cancel_kept`, `bill.status`, `bill.plan_limit_reached`, `bill.past_due_blocked_reply`, `bill.payment_success*`.
> **כלל קשיח:** אין חיוב בלי לחיצה על כפתור אישור, מהמספר המקושר שאליו נשלחה ההצעה, תוך 10 דקות. כל הצעת חיוב מציגה סכום כולל מע״מ ואת 4 הספרות האחרונות של הכרטיס. לחיצה מאוחרת → `bill.approval_expired` + הצעה חדשה, בלי חיוב.
> כפתורים: `[שדרוג עכשיו] [לא עכשיו]`, `[חיוב עכשיו] [לא עכשיו]`, `[חידוש עכשיו] [לא עכשיו]`, `[המשך מנוי] [לא עכשיו]`, `[בטל מנוי] [השאר פעיל]`, `[מעבר לבסיסי] [להישאר בפרו]`, `[להישאר בפרו] [לא עכשיו]`, ובתזכורות חיוב `[ניסיון חוזר] [עדכון כרטיס]`.
> כל שינוי במנוי — גם ביטול מעבר מתוכנן לבסיסי — רק בלחיצה. הצעת חיוב תקפה רק למחזור החיוב שלו חושבה: אם החיוב החודשי עבר בינתיים (או שהמנוי הושהה / המסלול השתנה), הלחיצה מקבלת `bill.offer_stale` ולא מחייבת.
> החודשיים הישנים `bill.past_due_day1/3/5` (`bot-copy.md`) הוחלפו ב-`bill.renewal_failed_day1/3/5` + `bill.renewal_paused` שבקובץ הזה: ההשהיה אחרי הכישלון של יום 7.
> פקודות בניסוח טבעי (בדיקה חיה של דניאל, 23.10.2026; `lib/billing/commands.ts`): שדרוג — "אני רוצה לשדרג למנוי פרו", "מנוי פרו", "לשדרג לפרו", "איך משדרגים?", "לשדרוג"; סטטוס — "איזה מנוי אני?", "באיזה מסלול אני?", "מה המסלול שלי?" (בניסיון: `bill.status_trial` ב-`bot-copy.md`). לא פקודה (נשאר לעוזרת): "איזו חבילה?" / "איזה מסלול?" בלי "אני" / "שלי" — אחרי מייל של חברת שליחויות זו חבילה, לא מנוי; ציווי בלי המסלול ("תשדרגי", "תשדרגי לי") — זו בקשה לשפר טיוטה. כל ניסוח אחר של שדרוג — העוזרת קוראת לכלי `start_upgrade`, וה-pipeline שולח את אותה הצעה בדיוק.

## הצעות

### `bill.upgrade_offer`
**מתי:** מסלול בסיסי — "שדרוג" או הגעה ל-750 הודעות. הסכום = ההפרש (200 ₪) × חלק התקופה שנותר בימים שלמים (מעוגל למעלה), מינימום 1 ₪. אחרי התשלום החיוב הבא הוא 299 ₪ במועד הרגיל.
**משתנים:** `{lead}` (אופציונלי — `bill.limit_lead`), `{amount}`, `{vat}`, `{days_left}`, `{period_end}`, `{next_amount}`, `{last4}`
```
{lead}

*שדרוג למסלול פרו*
עד 3,000 הודעות בחודש, שלושת הסוכנים המובנים ועד 3 סוכנים משלך, ואוטומציות — מיד.

לתשלום עכשיו: {amount} ₪ (כולל מע״מ {vat} ₪)
זה ההפרש היחסי עד סוף התקופה הנוכחית ({days_left}, עד {period_end}).
מ-{period_end}: {next_amount} ₪ לחודש.
החיוב בכרטיס המסתיים ב-{last4}. הקבלה תגיע לכאן ולמייל.

לשדרג?
```
`[שדרוג עכשיו] [לא עכשיו]`

### `bill.limit_lead`
**מתי:** הפסקה הראשונה של `bill.upgrade_offer` כשהמכסה נגמרה. הצעה אחת לכל היותר ב-6 שעות (נשלחת ההצעה — ורק אז נרשם הזמן); בין לבין כל הודעה מקבלת `bill.limit_reminder`. ההודעה האחרונה שנעצרה נשמרת (`pending_input`). בלי כרטיס שמיש — `bill.plan_limit_reached` (עם קישור התשלום) על כל הודעה.
**משתנים:** `{reset_date}`
```
הגעת ל-750 ההודעות של המסלול הבסיסי החודש. המכסה מתחדשת ב-{reset_date}, ותזכורות וסיכום הבוקר ממשיכים כרגיל.
```

### `bill.limit_reminder`
**מתי:** הודעה נוספת במכסה שנוצלה, בתוך 6 השעות שאחרי הצעת השדרוג — בלי הצעה (ובלי אישור) חדשה.
**משתנים:** `{reset_date}`
```
המכסה של המסלול הבסיסי לחודש הזה נוצלה (מתחדשת ב-{reset_date}), ולכן ההודעה הזו לא טופלה. לשדרוג למסלול פרו — לכתוב "שדרוג".
```

### `bill.retry_offer`
**מתי:** "ניסיון חוזר" / "תשלום" כשהחיוב החודשי לא עבר (או לחיצה מאוחרת על [ניסיון חוזר]).
**משתנים:** `{amount}`, `{vat}`, `{last4}`
```
*ניסיון חוזר לחיוב*
החיוב החודשי שלא עבר: {amount} ₪ (כולל מע״מ {vat} ₪), בכרטיס המסתיים ב-{last4}.

לחייב עכשיו?
```
`[חיוב עכשיו] [לא עכשיו]`

### `bill.renew_offer`
**מתי:** "חידוש מנוי" כשהמנוי מושהה או שהסתיים אחרי ביטול. חודש חדש מהיום.
**משתנים:** `{plan}`, `{amount}`, `{vat}`, `{period_end}`, `{last4}`
```
*חידוש מנוי {plan}*
לתשלום עכשיו: {amount} ₪ (כולל מע״מ {vat} ₪) — חודש, עד {period_end}.
החיוב בכרטיס המסתיים ב-{last4}. הקבלה תגיע לכאן ולמייל.

לחדש?
```
`[חידוש עכשיו] [לא עכשיו]`

### `bill.resume_offer`
**מתי:** "חידוש מנוי" כשהמנוי מבוטל אבל התקופה ששולמה עוד לא נגמרה — בלי חיוב.
**משתנים:** `{period_end}`, `{amount}`
```
המנוי מבוטל ופעיל עד {period_end}. להמשיך אותו? עכשיו לא יבוצע חיוב — החיוב הבא ({amount} ₪) יהיה ב-{period_end}, כרגיל.
```
`[המשך מנוי] [לא עכשיו]`

### `bill.cancel_confirm_paused`
**מתי:** "ביטול מנוי" כשהחשבון מושהה (אין "פעיל עד").
```
לבטל את המנוי? לא יהיו יותר ניסיונות חיוב, וההגדרות נשמרות 90 יום למקרה שתרצו לחזור.
```
`[בטל מנוי] [השאר פעיל]`

### `bill.keep_pro_confirm`
**מתי:** "שדרוג" במסלול פרו כשמעבר לבסיסי כבר מתוכנן. המעבר מתבטל רק בלחיצה.
**משתנים:** `{period_end}`, `{amount}` ("299")
```
המעבר למסלול הבסיסי מתוכנן ל-{period_end}. לבטל אותו ולהישאר בפרו? עכשיו לא יבוצע חיוב — החיוב הבא, ב-{period_end}, יהיה {amount} ₪ (במקום 99 ₪).
```
`[להישאר בפרו] [לא עכשיו]`

### `bill.downgrade_confirm`
**מתי:** "לעבור לבסיסי" במסלול פרו. נכנס לתוקף בחיוב הבא; אין החזר.
**משתנים:** `{period_end}`
```
לעבור למסלול הבסיסי? השינוי ייכנס לתוקף ב-{period_end}: עד אז נשארות כל היכולות של פרו, ומשם 99 ₪ לחודש (עד 750 הודעות, בלי הסוכנים המובנים, וסוכן אחד משלך: הוותיק נשאר פעיל, והשאר נשמרים נעולים). על התקופה הנוכחית אין החזר.
```
`[מעבר לבסיסי] [להישאר בפרו]`

## תוצאות

### `bill.upgrade_done`
**מתי:** החיוב של השדרוג עבר. אחריו — הודעת מסמך עם הקבלה.
**משתנים:** `{amount}`, `{next_amount}`, `{next_date}`, ושורת "לשלוח שוב" אם השדרוג הגיע מהמכסה
```
שודרג. מסלול פרו פעיל מעכשיו — עד 3,000 הודעות בחודש, שלושת הסוכנים המובנים זמינים, ואפשר ליצור עד 3 סוכנים משלך.
חויבו {amount} ₪. החיוב הבא: {next_amount} ₪ ב-{next_date}.
הקבלה בהודעה הבאה.

ההודעה האחרונה לא טופלה בגלל המכסה — אפשר לשלוח אותה שוב.
```

### `bill.charge_ok_resumed`
**מתי:** [ניסיון חוזר] עבר (בתקופת הניסיונות — המחזור ממשיך מתאריך החיוב; אחרי השהיה — חודש חדש מהיום).
**משתנים:** `{amount}`, `{next_date}`
```
החיוב עבר והחשבון פעיל. חויבו {amount} ₪; החיוב הבא: {next_date}.
הקבלה בהודעה הבאה.
```

### `bill.renewed`
**מתי:** [חידוש עכשיו] עבר.
**משתנים:** `{plan}`, `{amount}`, `{next_date}`
```
המנוי חודש — מסלול {plan} פעיל. חויבו {amount} ₪; החיוב הבא: {next_date}.
הקבלה בהודעה הבאה.
```

### `bill.resumed`
**מתי:** [המשך מנוי] — ביטול הביטול, בלי חיוב.
**משתנים:** `{period_end}`, `{amount}`
```
המנוי ממשיך. החיוב הבא: {amount} ₪ ב-{period_end}.
```

### `bill.downgrade_scheduled`
**מתי:** [מעבר לבסיסי], או "לעבור לבסיסי" כשהמעבר כבר נקבע.
**משתנים:** `{period_end}`
```
נקבע. מ-{period_end} המסלול יהיה בסיסי, 99 ₪ לחודש. עד אז הכול נשאר כמו שהוא. כדי להישאר בפרו — לכתוב "שדרוג".
```

### `bill.downgrade_kept`
**מתי:** [להישאר בפרו].
```
נשארים במסלול פרו. לא שיניתי כלום.
```

### `bill.downgrade_cleared`
**מתי:** [להישאר בפרו] על `bill.keep_pro_confirm` — המעבר מבוטל (בלי חיוב).
```
המעבר לבסיסי בוטל — נשארים במסלול פרו, והחיוב הבא כרגיל.
```

### `bill.keep_pro_declined`
**מתי:** [לא עכשיו] על `bill.keep_pro_confirm`.
```
בסדר, המעבר לבסיסי נשאר כמתוכנן. לא שיניתי כלום.
```

### `bill.offer_declined`
**מתי:** [לא עכשיו] על הצעת חיוב.
```
בסדר, לא בוצע חיוב ולא שיניתי כלום.
```

### `bill.renewal_charged`
**מתי:** החיוב החודשי האוטומטי עבר, בתוך חלון 24 שעות (מחוץ לחלון — תבנית `payment_receipt`). אחריו — הודעת מסמך.
**משתנים:** `{plan}`, `{amount}`, `{next_date}`
```
החיוב החודשי עבר: {amount} ₪, מסלול {plan}. החיוב הבא: {next_date}.
הקבלה בהודעה הבאה.
```

## שמירה על האישור

### `bill.approval_expired`
**מתי:** לחיצה על אישור אחרי יותר מ-10 דקות. אחריה — הצעה חדשה (סכום מחושב מחדש), בלי חיוב.
```
האישור הקודם כבר לא בתוקף (עברו יותר מ-10 דקות), ולכן לא בוצע חיוב. הנה הצעה מעודכנת:
```

### `bill.approval_used`
**מתי:** לחיצה שנייה על אותו אישור (או על הצעה שנדחתה) — לעולם לא חיוב שני.
```
ההצעה הזו כבר טופלה, ולא יבוצע חיוב נוסף.
```

### `bill.approval_wrong_number`
**מתי:** לחיצה ממספר שאינו המספר המקושר שאליו נשלחה ההצעה.
```
האישור הזה לא שייך למספר הזה, ולכן לא בוצע דבר.
```

### `bill.approval_not_found`
```
לא מצאתי את ההצעה הזו. אפשר לבקש שוב — למשל "שדרוג" או "ניסיון חוזר".
```

### `bill.charge_in_progress`
**מתי:** יש חיוב פתוח אחר (חיוב חודשי באמצע, או חיוב שתוצאתו לא ידועה) — לא מחייבים במקביל.
```
יש חיוב קודם שעדיין בבדיקה. כדי לא לחייב פעמיים, לא אבצע חיוב נוסף עד שיתברר — אעדכן כאן.
```

### `bill.offer_stale`
**מתי:** מצב המנוי השתנה בין ההצעה ללחיצה: החיוב החודשי עבר (מחזור חיוב אחר — הצעת שדרוג או ניסיון חוזר חושבה למחזור הקודם), המחזור הסתיים לפני הלחיצה, המנוי הושהה, המסלול השתנה.
```
המצב של המנוי השתנה מאז ההצעה, ולכן לא בוצע חיוב. אפשר לבקש שוב.
```

## כישלון חיוב (לא בוצע חיוב)

### `bill.charge_failed_declined`
**מתי:** חברת האשראי לא אישרה (למשל קוד 4). מצורפים `[ניסיון חוזר] [עדכון כרטיס]` עם אישור חדש.
**משתנים:** `{code}`, `{amount}`
```
החיוב לא עבר — חברת האשראי לא אישרה (קוד {code}), ולכן לא בוצע חיוב. אפשר לנסות שוב ({amount} ₪), או לעדכן כרטיס.
```

### `bill.charge_failed_card`
**מתי:** הכרטיס לא תקף לחיוב (חסום, טוקן לא תקף — 1, 2, 5, 15, 447, 997…). רק `[עדכון כרטיס]`.
**משתנים:** `{code}`
```
הכרטיס השמור לא אושר לחיוב (קוד {code}), ולכן לא בוצע חיוב. כדי להמשיך — עדכון כרטיס בדף המאובטח של HYP.
```

### `bill.charge_failed_temporary`
**מתי:** תקלת תקשורת (9, 999…). `[ניסיון חוזר] [עדכון כרטיס]`.
**משתנים:** `{amount}`
```
הייתה תקלת תקשורת מול חברת האשראי, ולא בוצע חיוב. אפשר לנסות שוב בעוד רגע ({amount} ₪).
```

### `bill.charge_failed_config`
**מתי:** תקלת הגדרה אצלנו (901 טוקנים כבויים, 902 PassP, 400 סכום שורות הקבלה…) — לא אשמת הלקוח.
```
יש תקלה זמנית במערכת התשלומים שלנו, ולא בוצע חיוב. כבר מטפלים בזה — אפשר לנסות שוב מאוחר יותר.
```

### `bill.charge_unknown`
**מתי:** אין תשובה מ-HYP (תקלת רשת אחרי השליחה). החיוב חסום עד בירור ידני בפורטל.
```
לא התקבלה תשובה ברורה מחברת האשראי. כדי לא לחייב פעמיים, לא אנסה שוב בינתיים — אבדוק ואעדכן כאן. אם החיוב עבר, הקבלה תגיע לכאן ולמייל.
```

```
תוקף הכרטיס השמור (מסתיים ב-{last4}) עבר, ולכן לא בוצע חיוב. כדי להמשיך — עדכון כרטיס בדף המאובטח של HYP.
```

## החיוב החודשי (ימים 1 / 3 / 5, השהיה אחרי יום 7)

### `bill.renewal_failed_day1`
**מתי:** החיוב ביום החידוש לא עבר. `[ניסיון חוזר] [עדכון כרטיס]`; מחוץ לחלון — תבנית `payment_failed`.
**משתנים:** `{amount}`, `{next_try}`
```
החיוב החודשי ({amount} ₪) לא עבר הפעם. השירות ממשיך כרגיל, ואנסה שוב ב-{next_try}.
אפשר גם לנסות שוב כבר עכשיו, או לעדכן כרטיס.
```

### `bill.renewal_failed_day3`
**משתנים:** `{amount}`, `{next_try}`
```
גם הניסיון השני לחייב ({amount} ₪) לא עבר. כדאי לבדוק עם הבנק או לעדכן כרטיס. אנסה שוב ב-{next_try}.
```

### `bill.renewal_failed_day5`
**משתנים:** `{amount}`, `{last_try}`
```
החיוב ({amount} ₪) לא עבר גם בניסיון השלישי. הניסיון האחרון יהיה ב-{last_try}; אם גם הוא לא יעבור, החשבון יושהה עד להסדרה — כל ההגדרות והחיבורים נשמרים.
```

### `bill.renewal_card_invalid`
**מתי:** החיוב החודשי נכשל בגלל הכרטיס — בלי ניסיונות אוטומטיים נוספים; השהיה ביום 7. `[עדכון כרטיס]`; מחוץ לחלון — `card_update_needed`.
**משתנים:** `{amount}`, `{until}`, `{code}`
```
החיוב החודשי ({amount} ₪) לא עבר: הכרטיס השמור לא אושר לחיוב (קוד {code}), ולכן לא אנסה אותו שוב. השירות ממשיך עד {until}. אחרי עדכון הכרטיס אפשר לחייב כאן בלחיצה.
```

### `bill.renewal_paused`
**מתי:** גם הניסיון של יום 7 נכשל — החשבון מושהה (past_due). `[ניסיון חוזר] [עדכון כרטיס]`; מחוץ לחלון — `account_paused`.


## קבלות וכרטיס

> דניאל קורא למסמך של HYP "קבלה" (לא "חשבונית") — כך בכל טקסט בשיחה. סוג המסמך עצמו נקבע בפורטל HYP (`docs/hyp-setup.md` §5).

### `bill.invoice_caption`
**מתי:** הכיתוב של הודעת המסמך (PDF) אחרי כל חיוב מוצלח.
**משתנים:** `{amount}`, `{date}`
```
קבלה — {amount} ₪, {date}
```

### `bill.invoice_link`
**מתי:** גיבוי כששליחת המסמך נכשלה.
**משתנים:** `{amount}`, `{date}`, `{link}`
```
קבלה — {amount} ₪, {date}:
{link}
```

### `bill.invoice_list`
**מתי:** "קבלה" / "קבלות" (וגם "חשבונית" כמילה נרדפת) — שלושת החיובים המוצלחים האחרונים.
**משתנים:** רשימה `{date}`, `{amount}`, `{desc}`, `{link}`
```
*הקבלות האחרונות*
• {date} — {amount} ₪ — {desc}
{link}

הקישורים תקפים ל-90 יום; כל הקבלות נשלחות גם למייל.
```

### `bill.invoice_none`
```
עדיין אין קבלות. אחרי החיוב הראשון הקבלה תגיע לכאן ולמייל.
```

### `bill.card_update_link`
**מתי:** [עדכון כרטיס] או "עדכון כרטיס". הקישור יוצר דף HYP חדש בכל פתיחה (J2 — אימות בלי חיוב).
**משתנים:** `{link}`
```
הנה דף מאובטח של HYP לעדכון הכרטיס — רק אימות, בלי חיוב:
{link}
הקישור תקף ל-7 ימים. בסיום העדכון יופיע אישור בדף.
```

### `bill.card_updated`
**מתי:** חזרה מאומתת מדף העדכון (CCode 600) והטוקן הוחלף, בתוך חלון 24 השעות (מחוץ לחלון — רק אם יש חיוב שלא עבר: התבנית `payment_failed`, או `account_paused` בהשהיה, עם `[ניסיון חוזר]`). אם יש חיוב שלא עבר — מצורפת `bill.retry_offer` עם `[חיוב עכשיו]` (החיוב רק בלחיצה). אם המנוי חיכה לעדכון כרטיס (כישלון מסוג "כרטיס") — הניסיונות האוטומטיים חוזרים ביום הניסיון הבא (3 / 5 / 7) עם הכרטיס החדש.
**משתנים:** `{last4}`
```
הכרטיס עודכן (מסתיים ב-{last4}). החיובים הבאים יהיו בכרטיס הזה.
```

### `bill.card_update_failed`
**משתנים:** `{link}`
```
עדכון הכרטיס לא הושלם, והכרטיס הקודם נשאר. אפשר לנסות שוב:
{link}
```

### `bill.card_update_charged`
**מתי:** דף עדכון הכרטיס חזר עם CCode 0 — המסוף ביצע חיוב אמיתי של 1 ₪ במקום בדיקת J2. הכרטיס לא מוחלף; שגיאה בלוג למפעיל (זיכוי ידני + הפעלת J2 במסוף, `docs/hyp-setup.md` §1, §8).
```
עדכון הכרטיס לא הושלם בגלל תקלה בהגדרות התשלום אצלנו, והכרטיס הקודם נשאר. אם הופיע חיוב של 1 ₪ על האימות — הוא יבוטל. כבר מטפלים בזה.
```

### `bill.refund_request`
**מתי:** "החזר כספי". החזרים מטופלים ידנית (`docs/hyp-setup.md` §8): הבקשה נרשמת ב-`audit_log` (`billing.refund_request`, עם העסקה האחרונה) ונכתבת שגיאה בלוג למפעיל, שעונה במייל.
```
בקשות להחזר כספי מטופלות ידנית, מול הקבלה. הבקשה נרשמה, והתשובה תישלח למייל של החשבון.
```
