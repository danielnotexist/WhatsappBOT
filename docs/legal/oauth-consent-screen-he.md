# טקסט גילוי לפני חיבור OAuth — Microsoft 365 ו-Google

> **טיוטה לבדיקת עו"ד — אינו ייעוץ משפטי.** 20.10.2026. הטקסטים מוצגים **באתר שלנו, לפני ההפניה** למסך ההרשאות של Microsoft/Google (מסך "חבר M365 / Google" באבן דרך 1), וגם בקישור החיבור שנשלח מהשיחה (`onb.connect_link`). מטרה: הסכמה מפורשת וספציפית (Microsoft APIs Terms §3(c), §5(a)), עמידה ב-Google Limited Use, ועמידה בסעיף 11 לחוק הגנת הפרטיות.

## 1. עקרונות
- שפה פשוטה, מה קורה בפועל, מה לא קורה, איך מבטלים.
- רשימת ההרשאות **המדויקת** שמבוקשת, בעברית, עם הסבר למה כל אחת.
- כפתור ההמשך = "ממשיכים לאישור ב-Microsoft" / "ממשיכים לאישור ב-Google" (לא "אישור" סתם).
- קישורים: מדיניות פרטיות, תנאי שימוש, דף ניתוק (myapps.microsoft.com / myaccount.google.com/permissions).
- אין סימון מראש (pre-checked) של כלום.

## 2. Microsoft 365 — מסך לפני ההפניה

**כותרת:** חיבור {{שם}} לחשבון Microsoft 365 שלך

**גוף:**
כדי שהעוזר יוכל לעבוד עם המייל, היומן והקבצים שלך, נבקש ממך לאשר ל-{{שם}} גישה לחשבון ה-Microsoft 365 שלך. החיבור הוא ישיר ומאובטח (OAuth) — הסיסמה שלך נשארת אצל Microsoft ואנחנו לא רואים אותה.

**מה {{שם}} יעשה עם הגישה, ורק לפי בקשה שלך בשיחה:**
- יקרא ויחפש מיילים כדי לסכם ולענות על שאלות ("מה רונית כתבה?")
- ינסח מיילים ו**ישלח אותם בשמך — רק אחרי שלחצת "שלח"** על הטיוטה
- יציג, יקבע, יזיז ויבטל פגישות ביומן — פעולה שמשפיעה על אחרים מתבצעת רק אחרי אישורך
- ימצא קבצים ב-OneDrive, יקרא Word / Excel / PowerPoint / PDF כדי לענות, וישתף קובץ רק באישורך
- יקבל התראה על מיילים חדשים כדי להכין את סיכום הבוקר

**מה {{שם}} לא עושה:** לא שומר את גוף המיילים והקבצים אצלנו (רק סיכומים ומזהים, ל-90 יום), לא משתמש בנתונים לפרסום, לא מוכר אותם, לא מאמן בהם מודלים, ולא ניגש לחשבונות אחרים בארגון.

**ההרשאות שיופיעו במסך של Microsoft (ולמה):**
| הרשאה | בשביל מה |
|---|---|
| `User.Read` | השם והמייל שלך, כדי לשייך את החיבור לחשבון |
| `Mail.ReadWrite` | קריאה, חיפוש וניסוח טיוטות |
| `Mail.Send` | שליחת מייל בשמך אחרי אישור |
| `Calendars.ReadWrite` | הצגה וניהול פגישות |
| `Files.Read.All` *(או `Files.ReadWrite` אם נדרש שיתוף)* | חיפוש וקריאת קבצים ב-OneDrive |
| `offline_access` | שהחיבור יישאר פעיל בלי להתחבר מחדש כל שעה |

**בארגון שלך ייתכן שנדרש אישור מנהל.** אם Microsoft מציגה הודעה כזו, נשלח לך טקסט קצר להעביר למנהל ה-IT, עם קישור לאישור חד-פעמי לארגון.

**איך מנתקים:** בכל רגע מהאזור האישי ב-{{שם}}, או ב-https://myapps.microsoft.com (ניהול "האפליקציות שלי"). הניתוק מוחק את הטוקנים אצלנו.

**הסכמה:** בלחיצה על "ממשיכים לאישור ב-Microsoft" אני מאשר/ת ל-{{שם}} להשתמש בגישה לחשבון ה-Microsoft 365 שלי למטרות המפורטות למעלה — כולל קריאה, סיכום, ניסוח ושליחה/עדכון בשמי לאחר אישורי לכל פעולה — ומצהיר/ה שקראתי את [מדיניות הפרטיות] ו[תנאי השימוש].
> הערת סגנון: כאן יוצא מן הכלל מותר "מאשר/ת" כי זו הצהרה משפטית בגוף ראשון של הלקוח; לחלופין: "אני מאשר בזאת" בניסוח ניטרלי "בלחיצה … ניתנת הסכמתי".

## 3. Google — מסך לפני ההפניה

**כותרת:** חיבור {{שם}} לחשבון Google שלך

**גוף:**
נבקש ממך לאשר ל-{{שם}} גישה ליומן Google, ל-Google Drive ולשליחת מייל מ-Gmail. החיבור ישיר ומאובטח (OAuth) — הסיסמה נשארת אצל Google.

**מה {{שם}} יעשה, רק לפי בקשתך:**
- יציג, יקבע, יזיז ויבטל פגישות ביומן (באישורך כשיש משתתפים)
- ימצא ויקרא קבצים שתשתף איתו ב-Drive, ויצרף קובץ למייל באישורך
- ישלח מיילים בשמך **רק אחרי לחיצה על "שלח"**
- **בשלב זה לא קורא את תיבת ה-Gmail** (היכולת תתווסף אחרי אישור האבטחה של Google, ותבקש הרשאה נפרדת)

**ההרשאות שיופיעו במסך של Google:**
| הרשאה | בשביל מה |
|---|---|
| `openid`, `email`, `profile` | זיהוי החשבון |
| `https://www.googleapis.com/auth/calendar` | הצגה וניהול פגישות |
| `https://www.googleapis.com/auth/drive.file` | גישה רק לקבצים שתפתח/תשתף דרך {{שם}} |
| `https://www.googleapis.com/auth/gmail.send` | שליחת מייל בשמך אחרי אישור |

**גילוי לפי מדיניות Google (Limited Use)** — חובה להציג במילים האלה (תרגום + המקור באנגלית):
השימוש של {{שם}} במידע שמתקבל מ-Google APIs, והעברתו לכל אפליקציה אחרת, יעמדו ב-[Google API Services User Data Policy](https://developers.google.com/terms/api-services-user-data-policy), כולל דרישות ה-Limited Use.
*{{שם}}'s use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.*

**מה {{שם}} לא עושה:** לא שומר תוכן קבצים או מיילים (רק סיכומים ומזהים, ל-90 יום), לא פרסום, לא מכירה, לא אימון מודלים, ולא העברה לאדם לצורך קריאה אלא באישורך או לצורכי אבטחה/חוק.

**איך מנתקים:** מהאזור האישי, או ב-https://myaccount.google.com/permissions.

**הסכמה:** בלחיצה על "ממשיכים לאישור ב-Google" ניתנת הסכמתי ל-{{שם}} להשתמש בגישה לחשבון Google שלי למטרות שלמעלה, לאחר אישורי לכל פעולה יוצאת, ואני מצהיר/ה שקראתי את [מדיניות הפרטיות] ו[תנאי השימוש].

**[ממשיכים לאישור ב-Google]** · [דילוג — לחבר אחר כך]

## 4. דרישות נלוות לאימות האפליקציה
- **Microsoft:** Publisher Verification (Partner Center, MPN ID) כדי שהמסך לא יציג "unverified"; שם האפליקציה = שם המוצר הסופי; לוגו; קישורי Terms/Privacy ברישום; multi-tenant; ב-admin-consent URL להשתמש ב-`/adminconsent` עם `state`.
- **Google:** OAuth consent screen External; `calendar` ו-`gmail.send` הם scopes **רגישים** → אימות (וידאו הדגמה של כל scope, מדיניות פרטיות באותו דומיין של האפליקציה, דף בית עם תיאור); `drive.file` לא רגיש. קריאת Gmail (`gmail.readonly`) = **restricted** → CASA Tier 2 (שלב 6).
- טקסט "unverified app" בתקופת הבדיקה — להסביר ללקוחות הראשונים.

## 5. מה לא אומת
1. רשימת ה-scopes הסופית של Microsoft (ייתכן ש-`Files.Read.All` מספיק, או ש-`Files.ReadWrite` נדרש לשיתוף קישור; `MailboxSettings.Read` לאזור זמן).
2. האם Microsoft דורשת את ההסכמה המפורשת לפי §3(c) **בתוך** תנאי השימוש בלבד או גם במסך — כאן שמנו בשניהם.
3. נוסח ה-Limited Use בעברית — Google דורשת את המשפט באנגלית כלשונו; התרגום רק לנוחות.
4. האם מותר "דילוג" לפני החיבור מבחינת Google (כן, זה רק האתר שלנו).
