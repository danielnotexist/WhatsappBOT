# {{שם}} — כל הטקסטים שהבוט שולח

> מסמך מקור לכל מחרוזת שיוצאת מהבוט בוואטסאפ. כל מחרוזת מזוהה ב-id קבוע (למשל `onb.welcome`) כדי שהקוד, הבדיקות וה-audit יפנו אליה בשם ולא בטקסט.
> כללי הסגנון המלאים ב-`style-guide.md`. תבניות Meta (מחוץ לחלון 24 שעות) ב-`wa-templates.md`.

**מוסכמות במסמך**
- `{{שם}}` — שם המוצר (placeholder עד שייבחר).
- משתנים בטקסט: `{name}`, `{business}`, `{link}` וכו'. רשימת המשתנים מופיעה ליד כל מחרוזת.
- `[שלח] [ערוך] [בטל]` — כפתורי Reply (עד 3). `(רשימה)` — List message (עד 10 שורות).
- כל הודעה היא בועה אחת. אם יש כמה חלקים, הם מופרדים בשורה ריקה בתוך אותה בועה (חיסכון בעלות ובקצב).
- ריאקשן ✅ על הודעת המשתמש נשלח תמיד לפני העיבוד. הוא לא נספר כהודעה ולא מופיע כאן.

## 1. קישור חשבון (`link.*`)

### `link.success`
**מתי:** הודעת הקישור ("היי! לקשר את החשבון שלי: ABCD-1234") הגיעה עם טוקן תקף שטרם נוצל. נשלחת מיד; מיד אחריה `onb.welcome`.
**משתנים:** `{name}` (אם ידוע מההרשמה; אחרת בלי פנייה בשם).
```
החשבון מקושר. מעכשיו אפשר לכתוב לי כאן.
```

### `link.token_expired`
**מתי:** הטוקן קיים אבל פג (יותר מ-15 דקות) או כבר נוצל.
**משתנים:** `{site_link}` (קישור לאזור האישי באתר, שם מייצרים קישור חדש).
```
הקישור הזה כבר לא בתוקף (הוא עובד 15 דקות ופעם אחת).
אפשר להפיק קישור חדש באזור האישי:
{site_link}
```

### `link.token_invalid`
**מתי:** ההודעה נראית כמו ניסיון קישור אבל הטוקן לא קיים.
**משתנים:** `{site_link}`
```
לא מצאתי קוד כזה. כדאי לבדוק שההודעה נשלחה בדיוק כמו שהופיעה באתר, או להפיק קישור חדש:
{site_link}
```

### `link.unknown_number`
**מתי:** הודעה ממספר שלא מקושר לאף חשבון, ולא מכילה טוקן. נשלחת פעם אחת למספר; אחרי 3 ניסיונות טוקן שגויים המספר נחסם בשקט (ללא הודעה).
**משתנים:** `{site_link}`
```
היי, כאן {{שם}} — עוזר למייל, ליומן ולקבצים של העסק.
המספר הזה עדיין לא מקושר לחשבון. ההרשמה לוקחת כדקה:
{site_link}
```

### `link.already_linked`
**מתי:** משתמש מקושר שולח שוב הודעת קישור עם טוקן של אותו חשבון.
**משתנים:** —
```
המספר הזה כבר מקושר לחשבון שלך. אפשר פשוט לכתוב לי מה צריך.
```

### `link.second_phone`
**מתי:** טוקן תקף של חשבון שכבר מקושר למספר אחר. לא מקשרים אוטומטית; מציעים החלפה דרך האתר (אבטחה: החלפת מספר רק מהאזור האישי).
**משתנים:** `{masked_phone}` (למשל "050-***-1234"), `{site_link}`
```
החשבון הזה כבר מקושר למספר אחר ({masked_phone}).
לכל חשבון יש מספר וואטסאפ אחד. כדי להעביר את החשבון למספר הזה, נכנסים לאזור האישי ובוחרים "החלפת מספר":
{site_link}
```

### `link.number_belongs_to_other`
**מתי:** טוקן תקף של חשבון א', אבל המספר השולח כבר מקושר לחשבון ב'.
**משתנים:** —
```
המספר הזה כבר מקושר לחשבון אחר. כדי לקשר אותו לחשבון חדש, קודם מנתקים אותו מהחשבון הקיים באזור האישי.
```

## 2. היכרות ראשונה (`onb.*`)

### `onb.welcome`
**מתי:** מיד אחרי `link.success`, פעם אחת בחיי החשבון. כולל את שורת האמון. הכפתורים: "סיור קצר" מתחיל את שאלות ההיכרות; "נתחיל לעבוד" מדלג ל-`onb.first_task`.
**משתנים:** `{name}` (אופציונלי).
```
שלום {name}, ברוכים הבאים ל-{{שם}}.
אני עוזר למייל, ליומן ולקבצים של העסק — ישירות מכאן.

חשוב לדעת: אני רואה רק מה ששולחים לי כאן. לא את שאר השיחות בוואטסאפ, ולא שום דבר שלא חיברת בעצמך.

רוצה סיור של דקה, או שנתחיל ישר לעבוד?
```
`[סיור קצר] [נתחיל לעבוד]`

> גרסה בלי שם: "ברוכים הבאים ל-{{שם}}." — בשאר זהה. ("ברוכים הבאים" היא צורת הברכה הניטרלית המקובלת; לא משתמשים ב-"ברוך הבא / ברוכה הבאה".)

### `onb.ways_card`
**מתי:** אחרי "סיור קצר". נשלח ככרטיס תמונה (image message) עם הטקסט הזה כ-caption. התמונה: איור של ארבע הדרכים (עיצוב בנפרד).
**משתנים:** —
```
*4 דרכים לעבוד איתי*

• *הקלטה* — מדברים, אני מתמלל ומבצע. "תנסח תשובה לרונית שאני מאשר את הפגישה."
• *מייל ויומן* — "מה יש לי מחר?", "מה רונית כתבה?", "תקבע פגישה ביום ג׳ ב-14:00."
• *קבצים* — "תמצא את ההסכם של כהן", "תשלח לי את ההצעה האחרונה ב-PDF."
• *תזכורות וסיכום בוקר* — "תזכיר לי מחר ב-9 להתקשר לבנק." וכל בוקר: פגישות, מיילים שמחכים, תזכורות.

כל שליחה החוצה — מייל, פגישה, קובץ — יוצאת רק אחרי אישור שלך בכפתור.
```

### `onb.first_task`
**מתי:** אחרי הכרטיס (או מיד אחרי "נתחיל לעבוד").
**משתנים:** —
```
ננסה משהו אמיתי. אפשר לשלוח הקלטה קצרה עם מה שעל הצלחת היום — או לכתוב משפט אחד, למשל: "מה יש לי מחר?"
```

### `onb.ask_name`
**מתי:** אחרי המשימה הראשונה (או אם המשתמש לא הגיב 2 דקות — נשאל בלי להמתין). אם השם ידוע מההרשמה — מדלגים.
**משתנים:** —
```
כדי שנדבר בנוח — איך לקרוא לך?
```

### `onb.ask_business`
**מתי:** אחרי השם.
**משתנים:** `{name}`
```
נעים להכיר, {name}. מה שם העסק או המשרד?
```

### `onb.ask_pain`
**מתי:** אחרי שם העסק. נשלח כ-List message (כפתור הרשימה: "לבחירה").
**משתנים:** —
```
מה הכי מעמיס עליך ביום-יום? זה עוזר לי לדעת במה להתמקד.
```
(רשימה — כותרת "מה הכי מעמיס"):
| id | כותרת (≤24 תווים) | תיאור (≤72 תווים) |
|---|---|---|
| `pain_email` | מיילים שמחכים לתשובה | תיבה מלאה, תשובות שנדחות |
| `pain_calendar` | היומן והפגישות | תיאומים, הזזות, שכחה |
| `pain_followup` | מעקבים ותזכורות | דברים שנופלים בין הכיסאות |
| `pain_files` | למצוא מסמכים | "איפה הקובץ ההוא?" |

### `onb.pain_ack`
**מתי:** אחרי בחירה ברשימה. ארבע גרסאות קצרות לפי הבחירה.
**משתנים:** —
```
pain_email    → מובן. אז נתחיל מהתיבה — אני מסכם מה מחכה ומנסח תשובות, והאישור נשאר אצלך.
pain_calendar → מובן. היומן אצלי — שאלות, קביעות והזזות, בלי לפתוח את Outlook.
pain_followup → מובן. תזכורות בשפה חופשית, וכל בוקר רשימה של מה שפתוח.
pain_files    → מובן. אומרים לי שם של לקוח או נושא, ואני מוצא את הקובץ ושולח.
```

### `onb.ask_morning_time`
**מתי:** אחרי `onb.pain_ack`. List message.
**משתנים:** —
```
כל בוקר אני יכול לשלוח סיכום קצר: פגישות היום, מיילים שמחכים לתשובה ותזכורות. באיזו שעה נוח?
```
(רשימה — כותרת "שעת סיכום בוקר"):
| id | כותרת |
|---|---|
| `mt_0700` | 07:00 |
| `mt_0730` | 07:30 |
| `mt_0800` | 08:00 |
| `mt_0830` | 08:30 |
| `mt_none` | לא עכשיו |

### `onb.morning_time_ack`
**מתי:** אחרי בחירת שעה.
**משתנים:** `{time}`
```
סגור. סיכום בוקר ב-{time}, בימי א׳–ה׳. אפשר לשנות בכל רגע — פשוט לכתוב לי.
```

### `onb.morning_time_skip`
**מתי:** אחרי "לא עכשיו".
**משתנים:** —
```
בסדר גמור. אם בהמשך יתאים לך סיכום בוקר — פשוט לכתוב "סיכום בוקר ב-7:30".
```

### `onb.connect_nudge`
**מתי:** אם אין חיבור M365/Google פעיל (דילגו באתר). קישור חד-פעמי ל-30 דקות. הכפתורים מפיקים קישור לספק הנבחר; "אחר כך" → `onb.connect_skip`.
**משתנים:** —
```
כדי שאוכל לעבוד עם המייל והיומן, צריך לחבר את החשבון. זה לוקח חצי דקה ועובד גם מהטלפון.
```
`[Microsoft 365] [Google] [אחר כך]`

### `onb.connect_link`
**מתי:** אחרי לחיצה על ספק. הקישור תקף 30 דקות ופעם אחת.
**משתנים:** `{provider}` ("Microsoft 365" / "Google"), `{link}`
```
הנה הקישור לחיבור {provider}:
{link}
הוא עובד פעם אחת, ל-30 הדקות הקרובות. אחרי האישור אני אעדכן כאן.
```

### `onb.connect_done`
**מתי:** ה-OAuth הושלם (callback). נשלח לוואטסאפ גם אם החיבור נעשה מהמחשב.
**משתנים:** `{provider}`, `{account_email}`
```
החיבור ל-{provider} הושלם ({account_email}). מעכשיו אפשר לשאול על מיילים, יומן וקבצים.
```

### `onb.connect_skip`
**מתי:** אחרי "אחר כך".
**משתנים:** —
```
בסדר. בלי חיבור אני יכול לעזור בתזכורות ובניסוח טקסטים. כשיתאים לחבר — לכתוב "לחבר את המייל" ואשלח קישור.
```

### `onb.done`
**מתי:** סוף ההיכרות (אחרי שעת הבוקר והחיבור, או הדילוג).
**משתנים:** `{name}`
```
זהו, אנחנו מסודרים. מכאן זה פשוט — כותבים או מקליטים מה צריך, ואני מטפל.
```

## 3. מצבי עיבוד (`proc.*`)

> כולם נשלחים אחרי ריאקשן ✅ ו-typing indicator. לא נספרים כהודעות. אם התשובה מגיעה תוך פחות מ-2 שניות — מדלגים על ההודעה ושולחים ישר את התשובה.

### `proc.one_sec`
**מתי:** בקשה שדורשת כלים (יומן/מייל/קבצים) וצפויה לקחת יותר מ-2 שניות.
```
רגע…
```

### `proc.listening`
**מתי:** התקבלה הודעה קולית; לפני התמלול.
```
מקשיב…
```

### `proc.searching_mail`
**מתי:** חיפוש במיילים (Graph search).
```
מחפש במיילים…
```

### `proc.searching_files`
**מתי:** חיפוש ב-OneDrive/Drive.
```
מחפש בקבצים…
```

### `proc.checking_calendar`
**מתי:** קריאת יומן.
```
בודק ביומן…
```

### `proc.drafting`
**מתי:** ניסוח מייל ארוך (אחרי שהחיפוש הסתיים).
```
מנסח…
```

### `proc.heartbeat_15s`
**מתי:** משימה שרצה יותר מ-15 שניות (סיכום של הרבה מיילים, קובץ גדול). נשלח פעם אחת; לא שולחים heartbeat נוסף עד 60 שניות.
**משתנים:** —
```
עדיין עובד על זה — עוד כמה שניות.
```

### `proc.heartbeat_60s`
**מתי:** חלפו 60 שניות. נשלח פעם אחת לכל היותר.
```
זה לוקח יותר מהרגיל. אני אעדכן כאן ברגע שיהיה מוכן, אין צורך לחכות על המסך.
```

### `proc.transcript_echo`
**מתי:** אחרי תמלול הקלטה, לפני הביצוע — רק כשההקלטה ארוכה מ-20 שניות או כשהביטחון בתמלול נמוך. בהקלטות קצרות וברורות מדלגים ומבצעים ישר.
**משתנים:** `{transcript}`
```
הבנתי כך: "{transcript}"
ממשיך לפי זה.
```

## 4. פעולות ואישורים (`act.*`)

> כל פעולה יוצאת (מייל, פגישה, שיתוף קובץ) נשמרת כ-`pending_action` עם תוקף 10 דקות. הכפתורים פועלים רק מאותו מספר. אחרי 10 דקות — `act.pending_expired`.

### 4.1 מייל

### `act.mail.draft`
**מתי:** הבוט ניסח מייל ומבקש אישור. ההודעה היא בועה אחת: כותרת, נמען, נושא, גוף בציטוט, וכפתורים.
**משתנים:** `{to_name}`, `{to_email}`, `{subject}`, `{body}`, `{cc}` (אופציונלי, שורה "עותק: …"), `{attachment}` (אופציונלי, שורה "מצורף: …")
```
*טיוטה למייל*
אל: {to_name} ({to_email})
נושא: {subject}

> {body}

לשלוח כך?
```
`[שלח] [ערוך] [בטל]`

> גוף המייל מוצג במלואו עד 1,200 תווים. ארוך יותר — מציגים את 600 התווים הראשונים, "…", ושורה: "המשך הטיוטה ({n} מילים) יישלח במלואו." לפני "לשלוח כך?".

### `act.mail.draft_reply`
**מתי:** כמו `act.mail.draft`, אבל זו תשובה על מייל קיים (Reply). מוסיפים שורת הקשר.
**משתנים:** כנ"ל + `{orig_date}` (למשל "יום ב׳ 19.10")
```
*טיוטת תשובה*
אל: {to_name} ({to_email})
נושא: Re: {subject}
בתגובה למייל מ-{orig_date}

> {body}

לשלוח כך?
```
`[שלח] [ערוך] [בטל]`

### `act.mail.sent`
**מתי:** אחרי לחיצה על "שלח" וקבלת 202 מ-Graph/Gmail.
**משתנים:** `{to_name}`
```
נשלח ל-{to_name}.
```

### `act.mail.edit_prompt`
**מתי:** אחרי "ערוך". נכנסים ללולאת עריכה: ההודעה הבאה של המשתמש היא הנחיית עריכה (לא בקשה חדשה).
**משתנים:** —
```
מה לשנות? אפשר לכתוב בחופשיות, למשל: "קצר יותר", "תוסיף שאני זמין ביום ה׳", או לשלוח נוסח משלך.
```

### `act.mail.edit_applied`
**מתי:** אחרי עריכה — מציגים את הטיוטה המעודכנת (אותו פורמט כמו `act.mail.draft`) עם כותרת שונה.
**משתנים:** כמו `act.mail.draft`
```
*טיוטה מעודכנת*
אל: {to_name} ({to_email})
נושא: {subject}

> {body}

לשלוח כך?
```
`[שלח] [ערוך] [בטל]`

### `act.mail.cancelled`
**מתי:** אחרי "בטל" על טיוטה.
```
בוטל. הטיוטה לא נשלחה ולא נשמרה.
```

### `act.mail.missing_recipient`
**מתי:** המשתמש ביקש לשלוח מייל אבל אין נמען ברור (לא נמצא באנשי הקשר / במיילים האחרונים).
**משתנים:** `{to_name}`
```
לא מצאתי כתובת מייל של {to_name}. אפשר לכתוב לי את הכתובת, או לשלוח לי מייל שלו ואזהה משם.
```

### `act.mail.summary`
**מתי:** תשובה ל-"מה מחכה לי במייל?" / "מה רונית כתבה?". פורמט: כותרת, עד 5 פריטים, שורת סיום עם הצעה. כל פריט: שולח — נושא — תמצית במשפט.
**משתנים:** `{count}`, פריטים `{from}`, `{subject}`, `{gist}`, `{when}`
```
*{count} מיילים שמחכים לתשובה*

• *{from}* — {subject}
  {gist} ({when})
• *{from}* — {subject}
  {gist} ({when})

רוצה שאנסח תשובה לאחד מהם?
```

## 5. שגיאות (`err.*`)

> הודעות שגיאה לא נספרות בניסיון. טון: עובדתי, קצר, תמיד עם צעד הבא. בלי "אופס", בלי התנצלויות כפולות.

### `err.connection_expired`
**מתי:** Refresh token נכשל (401/invalid_grant). קישור חד-פעמי ל-30 דקות. מחוץ לחלון 24 שעות — תבנית `reconnect_needed`.
**משתנים:** `{provider}`, `{link}`
```
החיבור ל-{provider} פג תוקף — זה קורה מדי פעם, בדרך כלל אחרי החלפת סיסמה.
כדי לחדש:
{link}
הקישור עובד פעם אחת, ל-30 הדקות הקרובות.
```

### `err.admin_consent_needed`
**מתי:** Microsoft החזיר AADSTS65001/90094 (נדרש אישור מנהל). הבוט מסביר במשפט ומציע טקסט מוכן להעברה למנהל ה-IT. שני חלקים בבועה אחת.
**משתנים:** `{admin_link}` (admin-consent URL של ה-tenant), `{tenant_name}`
```
בארגון שלך ({tenant_name}) חיבור של אפליקציות דורש אישור חד-פעמי של מנהל המערכת — ככה Microsoft מוגדרת היום ברוב העסקים.

אפשר להעביר למנהל ה-IT את ההודעה הזו כמו שהיא:

"היי, אני מחבר את {{שם}} — עוזר למייל וליומן בוואטסאפ — לחשבון ה-Microsoft 365 שלי. נדרש אישור מנהל חד-פעמי להרשאות מייל, יומן וקבצים (קריאה ושליחה בשמי בלבד, בלי גישה לחשבונות אחרים). הקישור לאישור:
{admin_link}
תודה."

אחרי האישור — לכתוב לי "חבר שוב" ואשלח קישור חדש.
```
> הערה: "אני מחבר" בציטוט — זו הודעה שהמשתמש שולח בשמו. מציגים "מחבר/ת"? לא — לפי מדיניות הסגנון אין קו נטוי. אם ידוע מגדר מהפרופיל, מתאימים ("מחברת"); אחרת ניסוח ניטרלי: "אני רוצה לחבר את {{שם}}…". הגרסה הניטרלית היא ברירת המחדל:
```
"היי, אני רוצה לחבר את {{שם}} — עוזר למייל וליומן בוואטסאפ — לחשבון ה-Microsoft 365 שלי. נדרש אישור מנהל חד-פעמי להרשאות מייל, יומן וקבצים (קריאה ושליחה בשמי בלבד, בלי גישה לחשבונות אחרים). הקישור לאישור:
{admin_link}
תודה."
```

### `err.admin_consent_pending`
**מתי:** המשתמש מנסה שוב לפני שהמנהל אישר.

```
עדיין אין אישור מנהל בארגון. ברגע שהוא יינתן, החיבור ייקח חצי דקה. אפשר לכתוב לי "חבר שוב" אחר כך.
```

## 6. ניסיון ותשלום (`bill.*`)

> ניסיון: 10 הודעות עם חיבור מלא. נספרות רק הודעות נכנסות שגוררות תשובה. התראה ב-3 וב-1, עצירה מנומסת ב-0, המשך מאותו מקום אחרי תשלום. תשלום דרך HYP, קישור אישי. מחוץ לחלון 24 שעות — תבניות (`wa-templates.md`).

### `bill.trial_left_3`
**מתי:** נשארו 3 הודעות. מצורף לסוף התשובה הרגילה כשורה אחרונה (לא בועה נפרדת).
**משתנים:** —
```
—
נשארו 3 הודעות בניסיון. אחרי זה המנוי: 99 ₪ לחודש.
```

### `bill.trial_left_1`
**מתי:** נשארה הודעה אחת. מצורף לסוף התשובה.
**משתנים:** `{pay_link}`
```
—
זו ההודעה הלפני-אחרונה בניסיון. כדי להמשיך בלי הפסקה:
{pay_link}
```

### `bill.trial_ended`
**מתי:** ההודעה ה-11 הגיעה. הבוט לא מבצע את הבקשה, שומר אותה (`pending_input`) ומציג את הקישור. מחוץ לחלון — תבנית `trial_ended_payment`.
**משתנים:** `{name}`, `{pay_link}`
```
{name}, 10 ההודעות של הניסיון נגמרו. תודה שניסית.

כדי להמשיך — מנוי של 99 ₪ לחודש (עד 750 הודעות), ביטול בכל רגע:
{pay_link}

ההודעה האחרונה שלך שמורה אצלי. ברגע שהתשלום יעבור, אמשיך ממנה.
```
> `{name}` בתחילת שורה — שם עברי בסדר. אם השם באותיות לטיניות (למשל "Dana"), להשתמש בגרסה: "10 ההודעות של הניסיון נגמרו, {name}. תודה שניסית." (ראו style-guide, כלל שם המשתמש.) "שניסית" — צורת עבר נוכח בעברית זהה לזכר ולנקבה.

### `bill.trial_ended_repeat`
**מתי:** הודעות נוספות אחרי סיום הניסיון (לא עונים לכל אחת; פעם ב-24 שעות לכל היותר).
**משתנים:** `{pay_link}`
```
הניסיון הסתיים. אני כאן ברגע שהמנוי יופעל:
{pay_link}
```

### `bill.payment_success`
**מתי:** redirect מ-HYP אומת (VERIFY) והטוקן נשמר. אם יש `pending_input` — מבצעים אותו מיד אחרי ההודעה הזו. מחוץ לחלון — תבנית `payment_success`.
**משתנים:** `{plan_name}` ("בסיסי" / "פרו"), `{invoice_note}` ("חשבונית נשלחה למייל.")
```
החשבון פעיל. תודה.
מסלול {plan_name}, {invoice_note}

ממשיך מאיפה שעצרנו.
```

### `bill.payment_success_no_pending`
**מתי:** כנ"ל, אבל אין בקשה ממתינה.
**משתנים:** `{plan_name}`, `{invoice_note}`
```
החשבון פעיל. תודה.
מסלול {plan_name}, {invoice_note}

מה עושים קודם?
```

### `bill.payment_failed_initial`
**מתי:** עסקת התשלום הראשונה נכשלה (CCode ≠ 0 ב-redirect).
**משתנים:** `{pay_link}`
```
התשלום לא עבר. לפעמים זה הבנק, לפעמים ספרה שגויה.
אפשר לנסות שוב, גם עם כרטיס אחר:
{pay_link}
```

### `bill.past_due_day1`
**מתי:** החיוב החודשי נכשל, ניסיון 1 (יום 1). השירות ממשיך לעבוד. תבנית `payment_failed` מחוץ לחלון.
**משתנים:** `{amount}` ("99"), `{update_link}`
```
החיוב החודשי ({amount} ₪) לא עבר הפעם. השירות ממשיך כרגיל, ואנסה שוב בעוד יומיים.
אם הכרטיס התחלף — אפשר לעדכן כאן:
{update_link}
```

### `bill.past_due_day3`
**מתי:** ניסיון 2 נכשל (יום 3).
**משתנים:** `{update_link}`
```
ניסיתי שוב לחייב והתשלום עדיין לא עובר. כדאי לבדוק עם הבנק או לעדכן כרטיס:
{update_link}
ניסיון אחרון בעוד יומיים; אחריו החשבון יושהה עד להסדרה.
```

### `bill.past_due_day5`
**מתי:** ניסיון 3 נכשל (יום 5). החשבון עובר להשהיה (past_due): הבוט עונה רק בהודעה הזו.
**משתנים:** `{update_link}`
```
החיוב לא עבר גם בניסיון השלישי, והחשבון מושהה. כל ההגדרות והחיבורים שמורים.
ברגע שהתשלום יוסדר — ממשיכים מאותו מקום:
{update_link}
```

### `bill.past_due_blocked_reply`
**מתי:** הודעה מהמשתמש בזמן השהיה (פעם ב-24 שעות).
**משתנים:** `{update_link}`
```
החשבון מושהה עד להסדרת התשלום:
{update_link}
```

### `bill.reactivated`
**מתי:** תשלום הוסדר אחרי השהיה.
```
החשבון פעיל שוב. ממשיכים.
```

### `bill.cancel_confirm`
**מתי:** המשתמש ביקש לבטל מנוי. אישור בכפתור לפני ביצוע.
**משתנים:** `{period_end}` ("30.11")
```
לבטל את המנוי? הוא יישאר פעיל עד {period_end}, ואחרי זה לא יחויב. ההגדרות נשמרות 90 יום למקרה שתרצו לחזור.
```
`[בטל מנוי] [השאר פעיל]`

### `bill.cancelled`
**מתי:** אחרי אישור הביטול.
**משתנים:** `{period_end}`
```
המנוי בוטל. אפשר להמשיך להשתמש עד {period_end}. לחזור בכל רגע — פשוט לכתוב "חדש מנוי".
```

### `bill.cancel_kept`
**מתי:** אחרי "השאר פעיל".
```
המנוי נשאר פעיל. לא שיניתי כלום.
```

### `bill.plan_limit_warn`
**מתי:** מסלול בסיסי, הגיעו ל-700 מ-750 בחודש. שורה בסוף תשובה.
**משתנים:** `{remaining}`, `{reset_date}`
```
—
נשארו {remaining} הודעות החודש במסלול הבסיסי (מתחדש ב-{reset_date}).
```

### `bill.plan_limit_reached`
**מתי:** 750 הודעות נוצלו במסלול בסיסי. מחוץ לחלון — תבנית `plan_limit_reached`.
**משתנים:** `{reset_date}`, `{upgrade_link}`
```
הגעת ל-750 ההודעות של המסלול הבסיסי החודש. המכסה מתחדשת ב-{reset_date}.

כדי להמשיך כבר עכשיו — מסלול פרו (299 ₪): עד 3,000 הודעות, סוכנים מובנים ואוטומציות:
{upgrade_link}

תזכורות וסיכום הבוקר ממשיכים לעבוד כרגיל.
```

### `bill.upgraded`
**מתי:** שדרוג לפרו אושר.
```
עברת למסלול פרו. המכסה החודשית עודכנה ל-3,000 הודעות, והסוכנים המובנים זמינים — "מה הסוכנים יודעים לעשות?" יסביר.
```

### `bill.status`
**מתי:** "מה המצב של המנוי שלי?" / "כמה הודעות נשארו?"
**משתנים:** `{plan_name}`, `{used}`, `{limit}`, `{next_charge}`, `{amount}`
```
*המנוי שלך*
מסלול: {plan_name}
הודעות החודש: {used} מתוך {limit}
חיוב הבא: {next_charge}, {amount} ₪

לשנות מסלול או לבטל — פשוט לכתוב.
```
